===== README =====

# LitMap Slim

A slimmer, local-first literature mapping tool built with **FastAPI + Jinja2 + HTMX**.

## What it does
- create and persist projects as JSON files;
- search a curated mock literature catalogue;
- review candidates and record **yes / no / defer** decisions;
- build a lightweight literature graph for accepted items;
- scan a local managed library for PDFs and supplements;
- prepare a retrieval board for missing files;
- export accepted literature metadata and discovered files into a LitCap-style handoff folder.

## Why this version is slimmer
- no React / TypeScript / Vite toolchain;
- one Python application owns views, workflow, persistence, and domain rules;
- HTMX keeps interactions dynamic without a SPA;
- graph rendering is a small SVG widget generated by the server.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .[dev]
uvicorn app.main:app --reload
```

Then open `http://127.0.0.1:8000`.

## Run tests

```bash
pytest -q
```

## Context-pack and repo maintenance tools

This repo includes lightweight context generation and git helper tooling so you can start a new chat and immediately attach compact, high-signal project context.

python scripts/repo_tool.py context

### Update context + run tests

```bash
python scripts/repo_tool.py update --run-tests
```

### Commit all changes

```bash
python scripts/repo_tool.py commit -m "Refine retrieval board"
```

### Commit and push

```bash
python scripts/repo_tool.py commit -m "Refine retrieval board" --push
```

### Shell shortcuts

```bash
./scripts/update_repo.sh
./scripts/commit_and_push.sh "Refine retrieval board"
```

## Context file design

The context generation deliberately stays small enough to be manageable:
- includes **repo intent**, **git state**, **tree**, **manifest**, and **important docs/config**;
- includes **verbatim code** for code/docs/templates/tests/scripts;
- excludes bulky folders like `.git`, `.venv`, caches, exports, and runtime data;
- excludes generated context outputs from the next context sweep to avoid recursive bloat.

That means the context pack is tuned for LLM handoff rather than raw archival completeness.
